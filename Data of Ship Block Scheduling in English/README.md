# Ship Block Scheduling Dataset

This README describes the structure and intended use of the English-version dataset for ship block scheduling research.

> **한국어 안내**  
> 이 데이터셋은 선박 블록을 제한된 작업 공간과 자원에 맞춰 배치·일정 계획하는 연구에 사용됩니다. 모델 입력값, 알고리즘별 일정 결과, 논문 그림 재현용 원자료로 구성되어 있습니다.

## Dataset Overview

This dataset supports research on **ship block scheduling under block-position constraints**. It provides:

- model input data (block attributes, block-position resources, and initial assignment state),
- scheduling outputs from heuristic and reinforcement learning methods,
- raw data used to reproduce key figures.

The files in this folder are the **English-version dataset** for publication and reuse.

> **한국어 해설**  
> 선박 블록의 특성, 작업 위치별 자원과 제약, 초기 배정 상태가 입력 데이터로 제공됩니다. 또한 휴리스틱·DDQN·EDDQN으로 생성한 일정 결과와 논문 그림을 다시 그릴 수 있는 원자료가 포함되어 있습니다.

---

## Research Hypothesis

The study is built around the following hypotheses:

1. Under realistic spatial/resource constraints in ship block construction, learning-based scheduling can produce better schedules than common heuristic rules.
2. Specifically, the enhanced DDQN method (EDDQN) is expected to improve schedule quality (e.g., lower delay days and better time-window satisfaction) compared with baseline heuristics and standard DDQN.
3. Better scheduling quality should be observable in both final scheduling outputs and training-performance trajectories.

> **한국어 해설**  
> 이 연구는 공간·자원 제약이 있는 실제 조선 환경에서 학습 기반 일정계획이 일반 휴리스틱보다 나은 결과를 낼 수 있다는 가설을 검증합니다. 특히 EDDQN이 기존 DDQN과 휴리스틱보다 지연을 줄이고 시간 제약을 더 잘 만족하는지, 그리고 그 개선이 최종 일정과 학습 과정 모두에서 나타나는지를 살펴봅니다.

## How the Data Was Gathered

The dataset combines three data layers:

1. **Operational input layer** (`Raw_input_ Data/`)
   - Block-side attributes: size, weight, processing time, time windows, and combination constraints
   - Block-position-side constraints: space, lifting capacity, height limit, and labor/team information
   - Initial assignment and status information

2. **Algorithm output layer** (`Result/`)
   - Schedules generated by multiple methods under the same problem setting
   - Heuristic, DDQN, and EDDQN outputs

3. **Figure reproduction layer** (`Figure6&7_raw_data/`, `Figure10_raw_data.xlsx`)
   - Raw experiment logs and statistics used to draw manuscript figures

All result files were exported from experiment runs and organized for reproducibility.

> **한국어 해설**  
> 데이터는 세 층으로 나뉩니다. `Raw_input_ Data/`에는 일정계획에 필요한 블록·작업 위치·초기 상태 정보가, `Result/`에는 방법별 일정 결과가, Figure 관련 파일에는 논문 그림 재현용 실험 기록과 통계가 들어 있습니다.

## Data Files and Their Meanings

### 1) Input Data (`Raw_input_ Data/`)

#### `block_information_table.xlsx`

Block-level production and scheduling attributes.

Typical fields include:

- block identifier / sequence,
- vessel identifier and vessel type,
- block type,
- dimensions and weight,
- processing time,
- earliest/latest start time and latest completion time,
- combination-related attributes (if applicable).

**Use:** Main job-side input for scheduling models.

> **한국어 해설**  
> 각 선박 블록의 식별자, 종류, 크기, 무게, 처리시간과 시작·완료 가능 시간 등의 정보를 담습니다. 일정계획 모델에서 “배정할 작업”에 해당하는 핵심 입력 파일입니다.

#### `initial_block_position_information.xlsx`

Initial assignment status between blocks and block positions.

Typical fields include:

- vessel/block identifiers,
- earliest start time,
- initial block-position description,
- expected completion time.

**Use:** Defines initial state and initialization constraints.

> **한국어 해설**  
> 실험 시작 시 어떤 블록이 어느 작업 위치에 배정되어 있는지와 예상 완료시간을 기록합니다. 모델의 초기 상태와 초기 제약을 정의하는 파일입니다.

#### `block_position_information.xlsx`

Resource and spatial constraints for block positions.

Typical fields include:

- block-position ID and description,
- area hierarchy,
- size/capacity limits,
- lifting capacity and height constraints,
- labor-team attributes,
- designated/general usage attributes.

**Use:** Spatial-resource side input for feasible assignment and scheduling.

> **한국어 해설**  
> 작업 위치별 크기·수용량·인양 능력·높이 제한·작업팀 등의 정보를 담습니다. 블록을 실제로 배정할 수 있는지 판단하는 공간·자원 측 입력 파일입니다.

### 2) Scheduling Output Data (`Result/`)

These files record schedules generated by heuristic strategies, DDQN, and enhanced DDQN (EDDQN).

Typical output fields include:

- planned start/finish time,
- latest allowed completion,
- delay days,
- earliness indicators,
- linked block and block-position identifiers.

**Use:** Method comparison, performance analysis, and result tables in the manuscript.

> **한국어 해설**  
> 방법별로 생성된 일정의 시작·종료시간, 허용 완료시간, 지연일수, 조기 완료 지표와 블록·작업 위치 식별자가 기록되어 있습니다. 같은 기준으로 파일을 비교하면 각 방법의 일정 품질을 평가할 수 있습니다.

### 3) Figure Reproduction Data

#### `Figure6&7_raw_data/DDQN_results.xlsx`

Raw training records for DDQN runs used to draw Figure 6/7.

#### `Figure6&7_raw_data/EDDQN_results.xlsx`

Raw training records for EDDQN runs used to draw Figure 6/7.

#### `Figure10_raw_data.xlsx`

Raw numerical data used to generate Figure 10.

**Use:** Direct reproducibility of reported figures.

> **한국어 해설**  
> Figure 6·7 파일은 DDQN과 EDDQN의 학습 안정성, 수렴 경향, 보상 변화 등을 확인하는 데 사용합니다. `Figure10_raw_data.xlsx`는 Figure 10을 다시 그릴 때 사용하는 수치 원자료입니다.

## What the Data Shows and Notable Findings

1. **Constraint-coupled scheduling behavior**
   - Schedules are jointly constrained by time windows, space, and resource limits.
   - Output files show how each method resolves these coupled constraints.

2. **Cross-method performance differences**
   - Files in `Result/` allow comparison of delay, earliness, and completion-time behavior across heuristics, DDQN, and EDDQN.
   - In this experiment design, EDDQN is intended to demonstrate improved scheduling quality relative to baseline strategies.

3. **Learning-process characteristics**
   - Figure 6/7 raw data allows inspection of training stability and convergence trends (e.g., reward progression) for DDQN versus EDDQN.

> **한국어 해설**  
> 이 데이터로 시간·공간·자원 제약이 일정에 함께 미치는 영향, 방법별 지연 및 완료시간 차이, DDQN과 EDDQN의 학습 안정성과 수렴 양상을 분석할 수 있습니다. 단, EDDQN의 우수성은 파일명이나 연구 의도만으로 단정하지 말고 동일한 지표로 실제 결과를 비교해 확인해야 합니다.

## How to Interpret and Use the Data

Recommended workflow:

1. **Load input constraints** from `Raw_input_ Data/`.
2. **Read one result file per method** from `Result/` and compute aggregate metrics such as:
   - total delay days,
   - average delay per block,
   - proportion of on-time completions,
   - earliness-delay tradeoff indicators.
3. **Compare methods using the same metric definitions**.
4. **Use the figure raw data** to reproduce manuscript plots.

Interpretation notes:

- Time fields should be treated as scheduling timestamps/time-window references from the original experiment setting.
- Block and block-position identifiers are keys for joining input and output records.
- Delay/earliness fields are direct indicators of schedule quality under constraints.

> **한국어 해설**  
> 먼저 입력 파일에서 제약 조건을 불러온 뒤, 각 방법의 결과 파일에서 총 지연일수·블록당 평균 지연·정시 완료율 등을 계산합니다. 공정한 비교를 위해 모든 방법에 동일한 지표 정의를 적용해야 합니다. 입력과 결과 파일은 블록 ID 및 작업 위치 ID로 연결할 수 있습니다.

## Key Concepts

| Term | Meaning | 한국어 |
|---|---|---|
| **block** | Production unit to be processed and scheduled | 처리하고 일정을 배정해야 하는 선박 생산 단위(선박 블록) |
| **block position** | Physical assembly/work position where a block is processed | 블록을 처리하는 물리적 조립·작업 위치 |
| **time window** | Allowed time range for starting or completing work | 작업의 시작 또는 완료가 허용되는 시간 범위 |
| **heuristic** | Rule-based method for constructing a schedule | 정해진 규칙에 따라 일정을 만드는 방법 |
| **DDQN / EDDQN** | Reinforcement-learning scheduling methods | 강화학습 기반 일정계획 방법과 그 개선형 |
