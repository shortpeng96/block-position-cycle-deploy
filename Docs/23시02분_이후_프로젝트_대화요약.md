# 23:02 이후 프로젝트 해석 정리

## 1. 7개 스케줄링 비교

7개 방법은 동일 Block에도 대부분 서로 다른 Position을 선택했다.

-   **Longest Processing** → Cycle 재현 최고, Delay는 상대적으로 큼
-   **Earliest Start** → Delay 성능 최고
-   **EDDQN** → Cycle 재현과 Delay 모두 상위권으로 가장 균형적
-   **DDQN** → 현재 두 평가축에서는 상대적으로 낮은 성능

따라서 **사전 Cycle을 잘 재현하는 스케줄과 Delay를 최소화하는 스케줄은
반드시 일치하지 않는다.**

## 2. Block Position Cycle 해석

`Block Position Cycle`은 스케줄링 Result가 아니라 Block Information
Table에 사전에 존재한다. 따라서 본 프로젝트에서는 이를 **스케줄링 이전에
설정된 Block별 기준 처리기간**으로 해석한다.

정확한 산정 방식은 공개되지 않았지만, 조선업에서는 작업시간·Man-hour를
전문가 경험, 과거 실적, 통계·머신러닝 등으로 사전에 산정할 수 있다. 다만
현재 데이터의 Cycle이 실제 ML 산출물인지는 확인할 수 없다.

## 3. Cycle은 다시 산정될 수 있음

Man-hour 선행연구는 하나의 고정값을 계속 예측하는 구조라기보다,
생산계획이 진행되며 새 정보를 반영해 작업시간을 다시 산정하는 구조에
가깝다.

``` text
초기 계획 → Cycle 1
스케줄링·생산정보 추가 → Cycle 2
실제 생산 진행 → Cycle 3
```

현재 데이터에는 최초의 `Block Position Cycle`만 있고 이후 재산정
Cycle이나 실제 실적 Cycle은 없다.

## 4. 현재 프로젝트가 분석한 것

``` text
사전 Block Position Cycle
        ↓
7가지 스케줄링
        ↓
서로 다른 Position / 일정
        ↓
① Position 결과가 사전 Cycle을 얼마나 재현하는가?
② 각 스케줄링 Result의 Delay는 얼마나 발생하는가?
```

즉 **사전 Cycle과 스케줄링 결과의 정합성을 회귀분석으로 비교하고, 각
방법의 Delay를 함께 분석한 것**이다.

## 5. 핵심 질문

처음에는 `Block Position Cycle`을 공기로 보고 예측하려 했지만,
최종적으로 다음 질문으로 확장되었다.

> **사전에 산정한 작업기간을 잘 반영하는 스케줄과 납기 지연을 최소화하는
> 스케줄은 같은가?**

현재 결과에서는 반드시 일치하지 않았으며, **EDDQN이 두 평가축에서 가장
균형적인 결과**를 보였다.

단, 실제 작업 실적 Cycle이 없으므로 Cycle 재현성이 낮다고 해서 실제 일정
준수 가능성이 낮다고 단정할 수는 없다.
