# 게시자 성능표와 본 프로젝트 분석 결과 비교

## 1. 비교 목적

데이터셋 게시자가 제시한 성능표는 `Makespan`, `Delayed Blocks`,
`Average Delay Time`, `Average Turnover Rate`,
`Normalized Average Utilization`을 기준으로 7개 스케줄링 방법을
평가한다.

본 프로젝트에서는 여기에 별도로 **Cycle Stability**라는 평가축을
추가하였다.

-   **Cycle Stability**: 각 스케줄링 방법이 선택한 Position 정보를
    동일한 회귀모델에 적용했을 때, 사전에 설정된
    `Block Position Cycle`을 얼마나 안정적으로 재현하는지를 의미한다.
-   본 분석에서는 Cycle RMSE가 낮을수록 Stability가 높은 것으로
    해석한다.

따라서 본 프로젝트는 원 연구의 성능평가를 단순 재현하는 것이 아니라,
**기존 스케줄링 평가 결과에 사전 Cycle과의 정합성이라는 새로운 관점을
추가하여 비교**한다.

------------------------------------------------------------------------

## 2. 게시자 결과와 본 프로젝트 Delay 분석의 일관성

게시자 성능표에서는 납기 관련 지표에서 다음과 같은 경향이 나타난다.

-   **EST (Earliest Start)**: Delayed Blocks 및 Average Delay Time에서
    가장 우수
-   **EDDQN**: 두 지표 모두 2위 수준
-   **SPT (Shortest Processing)**: 그다음 수준
-   **LPT (Longest Processing), DDQN**: 상대적으로 낮은 성능

본 프로젝트에서 Result 파일의 `delay days`를 직접 집계한
`Total Delay`에서도 거의 동일한 순서가 나타났다.

> **Earliest Start → EDDQN → Shortest Processing → 기타 방법 → Longest
> Processing → DDQN**

따라서 본 프로젝트의 Delay 분석은 게시자가 제시한 결과와 전반적으로
일관된 방향을 보였다.

------------------------------------------------------------------------

## 3. EDDQN의 균형적인 성능

게시자 성능표에서 EDDQN은 다음과 같이 여러 평가축에서 높은 성능을
보인다.

-   Makespan: **1위**
-   Delayed Blocks: **2위**
-   Average Delay Time: **2위**
-   Average Turnover Rate: **1위**
-   Normalized Average Utilization: **1위**

본 프로젝트에서 추가한 Cycle Stability에서도 EDDQN은 상위권에
위치하였다.

즉 EDDQN은 기존 연구에서 사용한 납기·활용도 관련 지표뿐 아니라, 본
프로젝트가 새롭게 추가한 **사전 Cycle 안정성 측면에서도 비교적 높은
성능**을 보였다.

따라서 현재 분석 범위에서는 EDDQN을 **특정 하나의 지표에 특화된
방법이라기보다 여러 평가축에서 균형적인 성능을 보이는 스케줄링
방법**으로 해석할 수 있다.

------------------------------------------------------------------------

## 4. Longest Processing의 Trade-off

`Longest Processing(LPT)`은 본 프로젝트의 Cycle Stability에서는 가장
높은 결과를 보였지만, 게시자 성능표에서는 Makespan, Delayed Blocks,
Average Delay Time 등이 모두 상대적으로 좋지 않았다.

이는 다음과 같은 중요한 결과를 보여준다.

> **사전에 설정된 Processing Cycle과 높은 정합성을 가지는 스케줄이
> 반드시 우수한 납기 성능을 만드는 것은 아니다.**

LPT가 높은 Cycle Stability를 보이는 정확한 원인은 현재 공개 자료만으로
확정할 수 없으며, 해당 휴리스틱의 구체적인 구현 규칙을 확인하기 전까지는
가설로 남겨둔다.

------------------------------------------------------------------------

## 5. Earliest Start와의 대비

`Earliest Start(EST)`는 게시자 성능표와 본 프로젝트 Delay 분석 모두에서
가장 우수한 납기 성능을 보였다.

반면 Cycle Stability에서는 LPT나 EDDQN보다 낮았다.

따라서 다음과 같은 대비가 나타난다.

``` text
Longest Processing
→ Cycle Stability 높음
→ Delay Performance 낮음

Earliest Start
→ Cycle Stability 중간
→ Delay Performance 높음

EDDQN
→ Cycle Stability 높음
→ Delay Performance 높음
```

이 결과는 **Cycle Stability와 납기 성능이 서로 다른 평가축이며, 두
성능이 반드시 같은 방향으로 움직이지 않음**을 보여준다.

------------------------------------------------------------------------

## 6. 결론에 반영할 핵심 내용

본 프로젝트는 기존 데이터셋에서 사용된 스케줄링 평가 지표를 그대로
반복하는 데 그치지 않고, `Block Position Cycle`을 사전 기준 처리기간으로
해석하여 **Cycle Stability라는 추가적인 평가 관점**을 제시하였다.

게시자 성능표와 본 프로젝트 결과를 비교한 결과, 기존 Delay 관련 성능의
전반적인 순위가 유사하게 재현되었으며, 여기에 Cycle Stability를 추가했을
때 각 스케줄링 방법의 특성이 더욱 분명하게 나타났다.

특히 LPT는 높은 Cycle Stability와 낮은 납기 성능이라는 Trade-off를
보였고, EST는 반대 성향을 나타냈다. 반면 EDDQN은 기존 스케줄링
성능지표와 Cycle Stability 모두에서 상위권을 보여 **현재 분석한 평가축을
종합했을 때 가장 균형적인 방법**으로 나타났다.

따라서 최종적으로는 단순히 "어떤 스케줄링 방법이 가장 우수한가"보다,

> **사전에 계획된 처리기간의 안정성, 납기 성능, 자원 활용 등 서로 다른
> 목적 사이에서 어떤 스케줄링 방법이 가장 적절한 균형을 만드는가?**

라는 관점에서 스케줄링 결과를 평가하는 것이 적절하다.

향후 비용, 실제 작업실적 Cycle, 인력·설비 사용량 등의 데이터가
확보된다면 Cycle Stability와 Delay뿐 아니라 **Cost까지 포함한 다목적
평가 구조**로 확장할 수 있다.
