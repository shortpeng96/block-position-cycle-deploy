## 최종 개발 방향 --- 동적 생산일정 의사결정 지원 시스템

이번 프로젝트는 `Block Position Cycle`을 예측하는 회귀분석에서
시작했지만, 분석 과정에서 사전 Cycle과 스케줄링 결과의 관계를 확인하고
7개 스케줄링 방법의 Position 선택, Cycle Stability, Delay Performance를
비교하는 방향으로 확장되었다.

향후에는 이번 분석을 **동적 생산일정 의사결정 지원 시스템**의 기초
단계로 활용하고자 한다.

### Phase 1. 현재 프로젝트 --- 분석 기반 구축

현재 단계에서는 다음 작업을 수행하였다.

-   Block / Position / Initial / Result 데이터 구조 파악
-   `Block Position Cycle`의 의미 재해석
-   회귀모델을 통한 사전 Cycle 설명
-   7개 스케줄링 방법의 Position 선택 차이 비교
-   Cycle Stability와 Delay Performance 비교
-   스케줄링 방법별 Trade-off 확인

즉 이번 프로젝트는 향후 시스템 개발을 위한 **데이터 구조와 평가기준을
이해하는 단계**로 볼 수 있다.

### Phase 2. 3D Scheduling Result Viewer 구현

다음 단계에서는 게시자가 제공한 7개 Scheduling Result를 활용하여 조선
Yard의 공간과 시간을 함께 확인할 수 있는 3D Viewer를 구현한다.

``` text
Scheduling Method 선택
        ↓
Block → Position 배치
        ↓
Planned Start / Finish → 시간축(Z)
        ↓
3D Yard Scheduling View
        ↓
Position / 구역 선택
        ↓
해당 영역 Gantt Chart 및 Block 정보 확인
```

초기 버전에서는 새로운 스케줄을 직접 생성하지 않고, **이미 계산된 7개
스케줄링 결과를 동일한 공간·시간 인터페이스에서 비교하는 Result
Viewer**에 집중한다.

Python·pandas를 이용해 Result Table을 처리하고, Streamlit 기반
인터페이스와 3D 시각화를 결합하여 프로토타입을 구현할 수 있다.

### Phase 3. 머신러닝·딥러닝 및 스케줄링 도메인 확장

향후 교육과정에서 학습하는 분류·군집·딥러닝 기법과 조선 생산 스케줄링
도메인을 결합하여 분석 기능을 확장한다.

-   **분류**: Block별 지연 위험 Low / Medium / High 분류
-   **군집**: 유사한 작업·물리 특성을 가진 Block 그룹 탐색
-   **이상탐지**: 비정상 Cycle, Delay 또는 Position 배정 탐색
-   **딥러닝·강화학습**: DDQN·EDDQN 등 학습 기반 스케줄링 방법의 구조
    이해 및 실험
-   **스케줄링 도메인 학습**: 목적함수, 제약조건, 자원배분, 공간
    스케줄링 및 다목적 최적화 이해

이를 통해 단순 Result Viewer를 **Scheduling Analyzer**로 발전시킨다.

### Phase 4. Dynamic Scheduling System

실제 생산실적과 현장상태를 반영할 수 있게 되면 정적인 결과 비교에서 동적
일정관리로 확장한다.

``` text
초기 Schedule
      ↓
실제 생산실적 및 현장 변화
      ↓
잔여 Cycle 재예측
      ↓
Delay / 자원상태 변화 감지
      ↓
Dynamic Rescheduling
      ↓
복수의 실행가능 Schedule 후보
      ↓
Cycle Stability / Delay / Cost / Utilization 비교
      ↓
생산관리자 의사결정
```

이 단계에서는 하나의 최적 일정만 자동으로 확정하기보다 **Top-k 실행가능
일정 또는 Pareto 후보**를 제시하고, 최종 선택은 생산관리자가 수행하는
Decision Support System 구조를 목표로 한다.

### Phase 5. Calendar-it 연계 --- 생산일정과 개인·팀 일정 연결

동적 스케줄링 결과를 Calendar-it과 연결하여 생산계획을 실제 담당자의
업무 일정으로 확장한다.

``` text
생산 Schedule
        ↓
Block 작업 일정
        ↓
담당자 / 협력사 업무
        ↓
준비 · 착수 · 검사 · 완료 Task
        ↓
Calendar-it 개인·팀 일정
```

이를 통해 공적인 생산일정과 개인·팀 단위의 업무일정을 연결하고, 일정
변경 시 관련 담당자가 변경사항을 함께 확인할 수 있는 협업 구조를
구현한다.

### Phase 6. ERP 개념 연계 --- 일정에 자원과 비용 추가

ERP 관점의 데이터를 추가하여 일정뿐 아니라 자재·인력·원가를 함께 평가할
수 있도록 확장한다.

-   자재 입고 및 구매 일정
-   Man-hour 및 작업조 부하
-   협력사 배정
-   인건비·설비비·물류비
-   Delay에 따른 비용 변화
-   스케줄링 방법별 자원·원가 비교

이를 통해 현재 프로젝트에서 평가하지 못한 **비용과 자원 관점의 스케줄링
성능**을 추가할 수 있다.

### Phase 7. 최종 확장 --- MES 연계

최종적으로는 생산계획과 실제 현장실적을 연결하는 MES 개념으로 확장한다.

``` text
ERP
자원 · 자재 · 원가
        ↓
Scheduling Decision Support
        ↕
3D Yard View
        ↕
Calendar-it
개인 · 팀 업무
        ↓
MES
작업지시 · 착수 · 실적 · 설비 · 품질 · 완료
        ↓
실제 생산현장
        ↓
실적 데이터 축적
        ↓
Cycle 재예측 및 Rescheduling
```

MES에서 수집된 실제 착수·완료시점, 생산량, Man-hour, 설비상태, 품질검사
및 재작업 정보를 다시 예측·스케줄링 시스템으로 전달하면 **계획 → 실행 →
실적 → 재예측 → 재스케줄링**이 반복되는 구조를 만들 수 있다.

### 최종 목표

> **현재의 회귀분석과 7개 스케줄링 비교를 출발점으로, 3D Scheduling
> Viewer → Scheduling Analyzer → Dynamic Scheduling → Calendar-it 협업
> 일정 → ERP 자원·원가 → MES 현장실적 연계 순으로 단계적으로 확장한다.**

궁극적으로는 머신러닝이 일정을 자동으로 결정하는 시스템보다, **현장
데이터와 여러 스케줄링 후보를 비교하여 생산관리자의 판단을 지원하고 실제
생산결과를 다시 다음 계획에 반영하는 데이터 기반 생산일정 의사결정 지원
시스템**을 목표로 한다.
