# Block Position Cycle 회귀분석 구조 재검토

## 1. 문제를 발견한 계기

Streamlit으로 7가지 스케줄링 방법의 결과를 시각화하는 과정에서 다음과
같은 의문이 생겼다.

> 스케줄링 방법에 따라 Position이 선택되고, 그에 따라 Position 및
> Initial 관련 정보가 결정되는 구조라면, Position과 Initial의 속성을
> Block Position Cycle 예측의 독립변수로 사용하는 것이 적절한가?

기존 분석에서는 다음과 같은 구조를 사용했다.

**Block 특성 + DDQN이 선택한 Position 특성 + Initial 정보 → Block
Position Cycle 예측**

그러나 Position은 Block 자체에 고정된 속성이 아니라 DDQN이라는 특정
스케줄링 방법론이 선택한 결과이다.

------------------------------------------------------------------------

## 2. 데이터의 실제 흐름

데이터의 구조를 다시 보면 다음과 같이 해석할 수 있다.

**Block 정보 + 야드/Position 조건 + Initial 상태 + Block Position
Cycle**

↓

**Scheduling Method** - DDQN - EDDQN - Earliest Start Time - Longest
Processing Time - Resource Utilization Based - Response Time Based -
Shortest Processing Time

↓

**Scheduling Result** - 선택된 Position - Planned Start Time - Planned
Finish Time - Delay / Advance 등

즉, 선택된 Position은 스케줄링 이전에 독립적으로 주어진 Block의 속성이
아니라 **스케줄링 알고리즘에 의해 결정되는 중간 결과 또는 결과 변수**에
가깝다.

예를 들어 동일한 Block이라도 스케줄링 방법에 따라 서로 다른 Position이
선택될 수 있다.

  -----------------------------------------------------------------------
  항목              DDQN              EDDQN             SPT
  ----------------- ----------------- ----------------- -----------------
  Block 특성        동일              동일              동일

  Scheduling Method DDQN              EDDQN             SPT

  선택 Position     P12               P07               P31

  Position 속성     선택 결과에 따라  선택 결과에 따라  선택 결과에 따라
                    결정              결정              결정
  -----------------------------------------------------------------------

따라서 7개 스케줄링 방법론을 비교하는 관점에서는 선택된 Position의
속성을 단순한 사전 독립변수로 취급하는 데 주의가 필요하다.

------------------------------------------------------------------------

## 3. Scheduling Method를 독립변수로 넣는 경우의 문제

처음에는 다음과 같은 구조를 생각할 수 있다.

**Block 정보 + Scheduling Method → Block Position Cycle**

하지만 여기에도 문제가 있다.

현재 데이터의 `Block Position Cycle`은 스케줄링 결과로 생성되는 값이
아니라 **스케줄링 이전부터 각 Block에 주어진 기준 처리기간**이다.

따라서 동일한 Block이라면 DDQN, EDDQN, SPT 등 어떤 스케줄링 방법을
적용하더라도 원래 주어진 Block Position Cycle 값 자체는 동일하다.

즉,

**Scheduling Method → Block Position Cycle**

이라는 인과 구조는 데이터 생성 과정과 맞지 않는다.

------------------------------------------------------------------------

## 4. 수정된 프로젝트 구조

따라서 프로젝트를 크게 두 단계로 분리하는 것이 논리적으로 더 자연스럽다.

### ① Machine Learning: Block Position Cycle 예측

**Block 고유 특성 → Block Position Cycle**

목적:

> 이 Block의 기준 처리기간은 어느 정도인가?

이 단계에서는 스케줄링 결과에 의해 결정되는 선택 Position 정보를 최종
독립변수에서 제외하고, Block 자체의 사전 정보를 중심으로 회귀모델을
구성한다.

------------------------------------------------------------------------

### ② Scheduling Comparison: 7가지 방법론 비교

**Block + Position + Initial + Cycle 등의 사전 조건**

↓

**7가지 Scheduling Method**

↓

**선택 Position / Planned Start / Planned Finish / Delay / Advance 등의
결과 비교**

목적:

> 동일한 작업 조건에서 스케줄링 방법에 따라 Block이 언제, 어디에
> 배치되는가?

이 단계에서 Position 및 Initial 데이터는 스케줄링의 조건과 결과를
이해하고 비교하는 데 활용한다.

------------------------------------------------------------------------

### ③ Streamlit Visualization

Streamlit에서는 7가지 스케줄링 결과를 공간 및 시간 관점에서 비교한다.

예:

**Scheduling Method 선택**

↓

**Block별 Position 배치 변화**

↓

**Planned Start / Finish에 따른 시간 변화**

↓

**스케줄링 방법론별 야드 운영 결과 비교**

따라서 현재 제작 중인 Streamlit 시각화는 수정된 프로젝트 구조에서도
그대로 활용할 수 있으며, 오히려 스케줄링 비교 단계의 목적에 더 잘
맞는다.

------------------------------------------------------------------------

## 5. 기존 분석은 어떻게 처리할 것인가?

기존의

**Block + DDQN Position + Initial → Block Position Cycle**

분석을 반드시 삭제할 필요는 없다.

이 분석은 최종 예측모델이라기보다 다음과 같은 **탐색적 분석**으로 해석할
수 있다.

> DDQN이 선택한 배치정보를 추가했을 때 Block Position Cycle에 대한
> 통계적 설명력이 어떻게 변화하는가?

다만 Position은 DDQN의 선택 결과이므로, Position 변수의 중요도가 높게
나타나더라도 이를 Block Position Cycle의 원인으로 해석해서는 안 된다.

최종 회귀모델에서는 데이터 생성 순서를 고려하여 Block 고유 특성을
중심으로 독립변수를 다시 구성하는 것이 더 타당하다.

------------------------------------------------------------------------

## 6. 발표/보고서에서의 설명

초기 분석을 단순한 실수로 표현하기보다는 데이터 구조를 분석하면서 모델
설계를 수정한 과정으로 설명할 수 있다.

> 초기에는 Position 정보를 Block Position Cycle 예측의 독립변수로
> 사용하였다. 그러나 스케줄링 결과를 비교하는 과정에서 Position이
> Block의 고유 속성이 아니라 각 스케줄링 방법론에 의해 선택되는 결과임을
> 확인하였다. 이에 데이터 생성 순서를 다시 검토하여 최종 Cycle 예측
> 모델은 Block 고유 특성을 중심으로 구성하고, Position 및 Initial 정보는
> 스케줄링 결과 비교 단계에서 활용하는 방향으로 분석 구조를 수정하였다.

------------------------------------------------------------------------

## 7. 최종 정리

기존 구조:

**Block + DDQN Position + Initial → Cycle 예측**

수정 구조:

**① Block 특성 → Block Position Cycle 예측**

**② Block / Position / Initial / Cycle 조건 → Scheduling Method →
Scheduling Result**

**③ Streamlit → 7개 Scheduling Result 공간·시간 시각화 및 비교**

따라서 프로젝트 전체를 폐기할 필요는 없지만, 최종 회귀모델의 독립변수
구성과 7개 스케줄링 비교의 목적은 수정하는 것이 타당하다.
